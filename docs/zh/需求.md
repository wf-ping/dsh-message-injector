# dsh-message-injector 全局需求文档

> 状态：已实现（经 `/grill-with-docs` 逐项确认），定位为「消息注入」插件。
> 术语定义见根目录 `CONTEXT.md`。

## 0. 开发红线（绝对禁止，触犯即违规）

1. **绝对禁止直接修改 dsh 的各项配置**：包括但不限于 `$DSH_HOME` 下的 profile/配置文件、dsh 自身 `node_modules`、dsh web 构建产物等一切 dsh 侧文件。
2. 所有改动**只允许发生在本项目**（`dsh-message-injector/`）代码内。
3. **测试插件可用性时，当且仅当使用官方的安装/卸载方式**，且**测试由用户亲自执行**：
   - 正式安装/卸载（官方命令）：`dsh plugin --profile <name> add|remove <package>`
   - 本仓库**不维护** `--patch` 本地开发加载配置，不使用该方式
4. **绝对禁止自启动 dsh 服务（如 `dsh web`、`dsh --profile` 等）做自动化测试/验证**——包括后台启动、临时启动、换端口启动。开发交付物是项目内代码与说明；安装、卸载、测试全部由用户亲自执行。
5. 任何"绕过官方机制、手改 dsh 配置来让插件生效"的做法都视为违规，立即停止并汇报。

## 1. 背景与目标

有些用户需要**每条消息**都自动带上固定内容——比如固定的指令前缀（`/grill-me`、`/code-review`）、固定的格式要求（"请用中文回答"）、或固定的工作流提示。手动每条消息都输入一遍很麻烦。

**目标**：提供 dsh 插件，让用户预设常用"注入内容"组合，选中后**每条消息自动注入**到输入框首行，一键启用、切换、停止。

> 演进说明：本项目最初定位为「技能预设自动填充」，后经分析确认——技能是**会话级激活**的，一个会话只需注入一次，手动输入一次即可，不值得插件化；而"**每条消息都注入固定内容**"才是真实且持续的需求，故更名 `dsh-message-injector` 并泛化内容为任意文本。

## 2. 概念（术语表）

| 术语 | 定义 |
|---|---|
| 预设组 | 一组有序注入内容行的集合，是配置和选择的基本单位 |
| 内容行 | 预设组内的一行注入内容；**以 `/` 开头**的行视为技能调用（如 `/grill-me`），其余为普通文本 |
| 预设选择器 | 输入框左下角的按钮 + 弹出菜单，用于查看、选择、反选预设组 |
| 当前预设组 | 用户当前选中的预设组；未选中任何组时不存在 |
| 反选 | 再次点击当前选中的组，取消选择，恢复"未选中"状态 |
| 自动注入 | 已选中预设组时，插件把内容行自动填入输入框首行的行为 |
| 注入守卫 | 注入前的检查规则：输入框去掉所有空白后为空才允许注入 |
| 有效内容 | 输入框去掉所有空白（含换行）后的剩余文本；非空即有有效内容 |
| 启用 / 禁用 | 预设组的开关状态；启用的组出现在选择器菜单中，禁用的隐藏 |
| 全局持久化 | 选择状态跨会话、跨刷新保持的存储行为 |

## 3. 使用流程（端到端）

### 3.1 配置阶段

在 **设置 → 插件 → 插件配置** 中对预设组做增删改查、启用/禁用。
启用的预设组会出现在输入框左下角的预设选择器菜单中。

### 3.2 选择阶段

1. 点击输入框左下角的预设选择器按钮，弹出菜单，列出**所有已启用的预设组**
2. 点击某项 = 选中，成为"当前预设组"（菜单中高亮；按钮上显示组名）
3. 可以一个都不选——未选中任何组时，**不做任何注入**
4. 再次点击当前选中项 = **反选**，回到未选中状态，**确保不再注入**
5. 选择状态**全局持久化**：跨会话、跨刷新保持，直到用户反选

### 3.3 自动注入阶段

1. 已选中预设组时，插件持续检测输入框状态（轮询，见 N2）
2. 检测到输入框**去掉所有空白后为空** → 把内容行注入输入框**首行**（空格连接为一行）
3. 注入前执行**注入守卫**：输入框内有有效内容（去掉空白后非空）→ **不注入**，绝不触碰已有内容
4. 注入后文本可自由编辑，由用户自行发送；发送后输入框清空，自动进入下一轮注入（**每条消息自动注入**）

> 说明：内容行中以 `/` 开头的技能调用会触发 dsh 技能激活；技能在会话内**持续生效**，重复注入同一技能会造成技能全文重复进入上下文（浪费 token）——若不需要"每条消息都带"，可反选停止，或期待"仅首条注入"模式（见 §7 畅想）。

## 4. 功能需求

### F1 预设组管理（设置 → 插件 → 插件配置）

- **CRUD**：预设组的增、删、改、查；**新增组插入列表首位（压栈）**，默认展开并自动滚动到可见位置
- **字段**：
  - 名称：必填，**唯一**（重名禁止保存）
  - 描述：可选，备注用途
  - 内容列表：有序，**至少 1 行**（空组禁止保存）；每行一条，`/` 开头视为技能调用
  - 启用：布尔，默认开启
- **组折叠**：组默认收起（只显示组名 + 启用开关 + 操作按钮），点击组名展开编辑
- **排序**：配置 UI 支持**预设组**上移/下移；内容行级排序属畅想
- **校验与边界**：见 F6

### F2 预设选择器（输入框左下角）

- **位置**：输入框左下角（紧邻权限选择器；**不改动权限选择器本身**）
- **菜单**：点击弹出，列出已启用的预设组；当前选中项高亮
- **反选**：点击当前选中项 = 取消选择
- **空态**：没有已启用的预设组时，菜单显示"暂无已启用的预设组"
- **设置入口**：菜单底部「设置」项，一键打开设置面板并切到「插件」分区（dsh 无公共 API；触发器按官方 aria 属性定位，分区按官方导航文案 zh/en 匹配；定位失败优雅降级——信号挂起，手动切分区后配置卡仍自动展开）；配置卡自动展开并滚动到可见位置（展示大部分配置内容）
- **按钮文案**：推荐显示当前组名；未选中时显示"预设"（实现细节，可调）
- **样式**：与权限选择器同款并随主题共变（见 N1）

### F3 选择状态

- **全局持久化**：选中状态写入持久存储，跨会话、跨刷新保持
- 反选之前持续生效
- **失效自动反选**：当前选中的组被删除或禁用时，自动回到未选中状态

### F4 自动注入

- **触发**：已选中预设组且输入框为空（去空白后）时注入
- **实现**：500ms 轮询检测输入框状态（见 N2）
- **内容格式**：内容行按序**空格连接为一行**注入；普通文本原样注入，技能调用行保持 `/` 前缀
- **位置**：填入输入框**首行**
- **可编辑**：注入的是普通文本，用户可在发送前自由增删改
- **频率**：每条消息注入（发送后清空 → 重新注入）

### F5 注入守卫

- 注入前检查输入框：去掉所有空白（含换行）后为**空** → 允许注入
- 有**有效内容** → 不注入，**绝不触碰已有内容**

### F6 校验与边界规则

核心原则：**配置期宽容（可保存但标记警告），运行期保守（缺失跳过，绝不破坏输入）**。

| # | 场景 | 规则 |
|---|---|---|
| 1 | 技能调用行（`/` 开头）对应的技能不存在 | 保存时校验并警告标记（⚠️），**允许保存**（技能可能之后才安装）；注入时跳过缺失项 |
| 2 | 空组（内容列表为空） | **禁止保存**（至少 1 行） |
| 3 | 组名重复 | **禁止保存** |
| 4 | 内容行重复 | 保存时自动去重（静默） |
| 5 | 全部组都禁用 | 选择器菜单显示空态提示"暂无已启用的预设组"；此时不注入 |
| 6 | 当前选中的组被删除或禁用 | 自动反选，回到未选中状态 |
| 7 | 注入时技能调用行全部缺失 | 不注入，输入框保持原样（静默；提示属畅想） |

## 5. 非功能需求

### N1 样式一致性（同主题共变）

- 预设选择器的按钮与菜单**复用 dsh 同一套样式挂钩**（设计令牌 / CSS 类 / 官方 Menu 组件），**不硬编码**颜色、圆角、字号等样式值
- 配置卡（设置 → 插件 → 插件配置）与 dsh 官方配置卡（WebSearch/Bash/AgentLoop）**同构**：可折叠标题栏 + 表单体 + 放弃/保存脚注；视觉参数照抄官方（卡：border l2、bg layer-3、radius 12px；input：34px 高、radius 8px、focus 品牌色描边；字段块间 border-top 分隔）
- 全部走 `--dsw-alias-*` 设计令牌；**禁止引用 dsh 内部 CSS 类名**（构建哈希，升级即断）
- **验收口径**：任何主题/皮肤插件改变权限选择器/官方配置卡的外观时，选择器与插件配置卡必须**同步变化**，始终保持视觉一致

### N2 实现方案约束

- **前端/后端双端**：选择器是浏览器 UI（前端），配置/校验/持久化在服务端（后端）
- **500ms 轮询**：检测输入框状态用轮询（已拍板），简单可靠
- **官方输入通道**：dsh 输入框是 React 受控组件，**禁止直接操作 DOM 改值**；注入文本须走官方程序化插入通道（`dsh-client-ui-input-trigger` 的作用域输入事件或 `input.setDraft`）
- **防重复注入**：注入后输入框非空，天然不会重复注入；用户手动删光内容后输入框变空，下一轮轮询会重新注入——这是预期行为（不需要请反选）
- **输入法保护**：中文输入法组合期间、输入框未聚焦时，跳过注入

### N3 可访问性与交互质量

- 选择器按钮与菜单的键盘可达性、ARIA 属性与权限选择器保持一致
- 菜单打开、选中、反选的状态变化有明确视觉反馈

## 6. 技术约束（已核实的事实）

| 事实 | 说明 |
|---|---|
| 权限选择器按钮 | 输入区左下角第二个按钮，点击可见 Full Access；本质是 dsh 的 `PermissionSelect` 组件。插件放在它附近，不动它 |
| skill 激活机制 | skill 是"用户可调用"（`isUserInvocable`），用户输入 `/grill-me` 形式触发加载；**会话级激活**，一次触发当前会话持续生效；重复注入同一技能会造成技能全文重复进入上下文（无去重逻辑） |
| 插件配置入口 | dsh 设置 → 插件 → 插件配置 渲染插件的配置卡（`settings.plugin.item` 槽，key = 命名空间） |
| 输入注入通道 | 官方通道 `input.setDraft(text)`（React 受控组件，禁止直接改 DOM）；判空读 `input.state.getSnapshot()`（draft/phase） |
| 插件形态 | 双端插件：后端（配置 schema + settings 接线 + validate）、前端（预构建 JS bundle，`window.__ModuleLoader__.load` 形态）；`dsh.bundle` 声明让 `dsh plugin add` 挂载为 profile 层 |

**待实现时验证**：
- 一条消息中多个技能指令是否全部激活、激活顺序是否与文本顺序一致

## 7. 畅想（待决策）

> 以下均为**畅想**，未进入 V1 范围，标记待决策。按"价值高、成本低"优先排序。

1. **拦截轻提示**：注入被守卫拦截时，在输入框附近短暂 toast 提示。价值：消除"我点了吗"的困惑。成本：低。
2. **内容占位符/变量**：内容支持 `{file}`、`{workspace}` 等占位符，注入时替换为当前上下文。价值：高。成本：中。
3. **仅首条注入模式**：可选项——选中组后只在当前会话第一条消息前注入一次（技能已会话级激活，可避免重复注入浪费 token）。价值：高（省 token）。成本：低。
4. **默认组 / 工作区自动切换**：为指定工作区（目录）绑定默认预设组，进入该工作区的会话自动应用。价值：中高。成本：中高。
5. **会话级临时豁免**：全局选中某组时，允许在单个会话内临时关闭（不影响全局选择）。价值：中。成本：中。
6. **预设组导入/导出**：JSON 文件形式分享预设组。价值：中。成本：低。
7. **快捷键切换**：如 Ctrl+1..9 快速切换预设组、一键反选。价值：中。成本：低。
8. **组图标/颜色标记**：预设组可配图标与颜色。价值：低中。成本：低。
9. **拖拽排序**：配置界面拖拽调整内容行顺序。价值：低。成本：中。
10. **多组叠加**：允许同时选中多个预设组，注入时合并（去重）。价值：低中。成本：中。
11. **使用统计**：记录各预设组使用次数，配置界面展示。价值：低。成本：低中。
12. **社区模板市场**：预设组模板的共享仓库。价值：远期想象。成本：高。
