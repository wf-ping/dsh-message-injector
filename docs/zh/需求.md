## 1. 背景与目标

开发时经常需要启用某些 skill（如 `/grill-me`），但每次对话前手动输入一次很麻烦。

**目标**：提供一个 dsh 插件，让用户预设常用 skill 组合，选中后自动填充到输入框首行，一键启用、切换、停止，全程无需手打技能指令。

## 2. 概念（术语表）

| 术语 | 定义 |
|---|---|
| 预设组 | 一组有序 skill 名称的集合，是配置和选择的基本单位 |
| 预设选择器 | 输入框旁的按钮 + 弹出菜单，用于查看、选择、反选预设组 |
| 当前预设组 | 用户当前选中的预设组；未选中任何组时不存在 |
| 反选 | 再次点击当前选中的组，取消选择，恢复"未选中"状态 |
| 自动填充 | 已选中预设组时，插件自动把技能文本填入输入框首行的行为 |
| 填充守卫 | 填充前的检查规则：输入框去掉所有空白后为空才允许填充 |
| 有效内容 | 输入框去掉所有空白（含换行）后的剩余文本；非空即有有效内容 |
| 启用 / 禁用 | 预设组的开关状态；启用的组出现在选择器菜单中，禁用的隐藏 |
| 全局持久化 | 选择状态跨会话、跨刷新保持的存储行为 |

## 3. 使用流程（端到端）

### 3.1 配置阶段

在 **设置 → 插件 → 插件配置** 中对预设组做增删改查、启用/禁用。
启用的预设组会出现在输入框旁的预设选择器菜单中。

### 3.2 选择阶段

1. 点击输入框旁的预设选择器按钮，弹出菜单，列出**所有已启用的预设组**
2. 点击某项 = 选中，成为"当前预设组"（菜单中高亮；按钮上显示组名）
3. 可以一个都不选——未选中任何组时，**不做任何填充**
4. 再次点击当前选中项 = **反选**，回到未选中状态，**确保不再填充**
5. 选择状态**全局持久化**：跨会话、跨刷新保持，直到用户反选

### 3.3 自动填充阶段

1. 已选中预设组时，插件持续检测输入框状态（轮询，见 N2）
2. 检测到输入框**去掉所有空白后为空** → 把技能文本填入输入框**首行**，一行、空格分隔，如 `/grill-me /domain-modeling`
3. 填充前执行**填充守卫**：输入框内有有效内容（去掉空白后非空）→ **不填充**，绝不触碰已有内容
4. 填充后文本可自由编辑，由用户自行发送；发送后输入框清空，自动进入下一轮填充（每条消息自动带技能）

> 说明：skill 在 dsh 中是**会话级激活**的——一次触发，当前会话持续生效。因此"每条消息都带技能"对用户无副作用，不会重复加载。

## 4. 功能需求

### F1 预设组管理（设置 → 插件 → 插件配置）

- **CRUD**：预设组的增、删、改、查
- **字段**：
  - 名称：必填，**唯一**（重名禁止保存）
  - 描述：可选，备注用途
  - 技能列表：有序，**至少 1 个**（空组禁止保存）
  - 启用：布尔，默认开启
- **排序**：配置 UI 支持技能列表上移/下移（调整填充顺序；拖拽属畅想）
- **校验与边界**：见 F6

### F2 预设选择器（输入框工具栏）

- **位置**：输入区左下角第二个按钮（权限选择器，点击可见 Full Access，即 dsh 的 `PermissionSelect` 组件）**之后**；**不改动权限选择器本身**
- **菜单**：点击弹出，列出已启用的预设组；当前选中项高亮
- **反选**：点击当前选中项 = 取消选择
- **空态**：没有已启用的预设组时，菜单显示"暂无已启用的预设组"
- **按钮文案**：推荐显示当前组名；未选中时显示"预设"（实现细节，可调）
- **样式**：与权限选择器同款并随主题共变（见 N1）

### F3 选择状态

- **全局持久化**：选中状态写入持久存储，跨会话、跨刷新保持
- 反选之前持续生效
- **失效自动反选**：当前选中的组被删除或禁用时，自动回到未选中状态（避免"选中一个看不见的组"）

### F4 自动填充

- **触发**：已选中预设组且输入框为空（去空白后）时填充
- **实现**：500ms 轮询检测输入框状态（见 N2）
- **文本格式**：组内技能按序拼接为**一行**，空格分隔，如 `/grill-me /domain-modeling`
- **位置**：填入输入框**首行**
- **可编辑**：填充的是普通文本，用户可在发送前自由增删改

### F5 填充守卫

- 填充前检查输入框：去掉所有空白（含换行）后为**空** → 允许填充
- 有**有效内容** → 不填充，**绝不触碰已有内容**

### F6 校验与边界规则

核心原则：**配置期宽容（可保存但标记警告），运行期保守（缺啥跳啥，绝不破坏输入）**。

| # | 场景 | 规则 |
|---|---|---|
| 1 | skill 名称不存在（拼错、未安装） | 保存时校验并警告标记（如名称旁 ⚠️），**允许保存**（skill 可能之后才安装）；填充时跳过缺失项 |
| 2 | 空组（技能列表为空） | **禁止保存**（至少 1 个技能） |
| 3 | 组名重复 | **禁止保存** |
| 4 | 组内重复 skill | 保存时自动去重并提示 |
| 5 | 全部组都禁用 | 选择器菜单显示空态提示"暂无已启用的预设组"；此时不填充 |
| 6 | 当前选中的组被删除或禁用 | 自动反选，回到未选中状态 |
| 7 | 填充时组内技能全部缺失 | 不填充，输入框保持原样（静默；提示属畅想） |

## 5. 非功能需求

### N1 样式一致性（同主题共变）

- 预设选择器的按钮与菜单**复用 dsh 同一套样式挂钩**（设计令牌 / CSS 类 / 官方 Menu 组件），**不硬编码**颜色、圆角、字号等样式值
- **验收口径**：任何主题/皮肤插件改变权限选择器（PermissionSelect）的外观时，预设选择器必须**同步变化**，两者始终保持视觉一致

### N2 实现方案约束

- **客户端插件**：选择器是 Web UI，插件须以客户端插件形态运行（dsh web 注入 `window.__DSH_BOOT__` 的同一前端环境）
- **500ms 轮询**：检测输入框状态用轮询（已拍板），简单可靠；对"输入框变空"的感知延迟无感
- **官方输入通道**：dsh 输入框是 React 受控组件，**禁止直接操作 DOM 改值**；填充文本须走官方程序化插入通道（`dsh-client-ui-input-trigger` 的作用域输入事件，如 `slash/input-insert-text`，经会话 scope carrier 分发）
- **防重复填充**：填充后输入框非空，天然不会重复填；用户手动删光技能文本后输入框变空，下一轮轮询会填回——这是预期行为（发纯文本请反选），不是 bug
- **输入法保护**：中文输入法组合期间、输入框未聚焦时，跳过填充，避免干扰光标与文本

### N3 可访问性与交互质量

- 选择器按钮与菜单的键盘可达性、ARIA 属性与权限选择器保持一致
- 菜单打开、选中、反选的状态变化有明确视觉反馈

## 6. 技术约束（已核实的事实）

| 事实 | 说明 |
|---|---|
| 权限选择器按钮 | 输入区左下角第二个按钮，点击可见 Full Access；本质是 dsh 的 `PermissionSelect` 组件（`/permission` 命令）。插件放在它后面，不动它 |
| skill 激活机制 | skill 是"用户可调用"（`isUserInvocable`），用户输入 `/grill-me` 形式触发加载；模型侧另有 `skill` 工具。技能在会话内持续激活 |
| 插件配置入口 | dsh 设置 → 插件 → 插件配置 渲染 Cordis 插件的 config schema（表单化配置），预设组 CRUD 依托该机制 |
| 输入插入通道 | `dsh-client-ui-input-trigger` 提供作用域输入事件（`slash/input-insert-text` 等）与 `@` `/` 候选管线；v1 选择器不接入候选管线，仅用官方事件做文本插入 |
| 插件形态 | Cordis 插件：`cordis.yml` 经 `insert` 引入入口绝对路径；入口导出 `apply(ctx)`；依赖服务用 `inject` 声明；`ctx.effect()` 管理手动清理的资源 |

**待实现时验证**（写进开发任务）：
- 一条消息中多个 skill 指令（如 `/grill-me /domain-modeling`）是否全部激活、激活顺序是否与文本顺序一致
- 空输入框场景下 `slash/input-insert-text` 事件插入首行的具体调用方式（span/CAS 参数）

## 7. 畅想（待决策）

> 以下均为**畅想**，未进入 V1 范围，标记待决策。按"价值高、成本低"优先排序，供后续排期参考。

1. **拦截轻提示**：填充被守卫拦截时，在输入框附近短暂 toast 提示（如"输入框已有内容，未填充"）。价值：消除"我点了吗"的困惑。成本：低。
2. **技能参数化**：预设组内技能支持带参数，如 `/grill-me docs/zh/需求.md`，点击时自动拼接目标文件路径。价值：高（grilling 常针对具体文档）。成本：中。
3. **自由文本片段**：组内可混入非 skill 的指令文本（如"请用中文回答"、"只读模式"）。价值：中高。成本：低。
4. **默认组 / 工作区自动切换**：为指定工作区（目录）绑定默认预设组，进入该工作区的会话自动应用；或按当前打开的文件/工作区智能推荐。价值：中高（消灭"每次点选"）。成本：中高，且与 F3 全局持久化需定义优先级。
5. **会话级临时豁免**：全局选中某组时，允许在单个会话内临时关闭（不影响全局选择）。价值：中，化解"串台"痛点。成本：中。
6. **预设组导入/导出**：JSON 文件形式分享预设组（如团队统一审查流程）。价值：中。成本：低。
7. **快捷键切换**：如 Ctrl+1..9 快速切换预设组、一键反选。价值：中。成本：低。
8. **组图标/颜色标记**：预设组可配图标与颜色，选择器菜单内区分。价值：低中。成本：低。
9. **拖拽排序**：配置界面拖拽调整技能顺序（替代上移/下移按钮）。价值：低。成本：中。
10. **多组叠加**：允许同时选中多个预设组，填充时合并（去重）。价值：低中（组合的组合）。成本：中，与单选模型冲突，需重新设计选择器交互。
11. **使用统计**：记录各预设组使用次数/会话数，配置界面展示，辅助用户优化组合。价值：低。成本：低中。
12. **社区模板市场**：预设组模板的共享仓库。价值：远期想象。成本：高，V1 不考虑。
