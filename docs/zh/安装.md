# 安装

有两种安装方式，**更新方式不同**，请按需选择：

| 方式 | 装的是什么 | 如何更新 |
|---|---|---|
| 本地路径安装 | **软链接**，指向你的仓库 | 改代码后 `pnpm build` + 重启 dsh 即生效，无需重装 |
| GitHub 安装 | **克隆副本**，与本地代码无关 | 重新执行 add 拉取最新（本地改动不影响已装副本） |

## 本地路径安装（开发用）

在仓库目录内执行：

```bash
pnpm install:plugin       # 安装（等价于 dsh plugin --profile web add "$PWD"）
pnpm uninstall:plugin     # 卸载
```

也可以手动指定路径：

```bash
dsh plugin --profile web add <仓库路径>             # 安装
dsh plugin --profile web remove dsh-skill-injector  # 卸载
```

**改代码后的迭代**（软链接指向仓库，改完即生效）：

```bash
pnpm build        # 重新生成 lib/（把 src/ 的源码翻译成 dsh 能读取的 JS）
# 然后重启 dsh web 生效
```

`lib/` 里的构建产物已提交在仓库中，所以**首次安装无需 build**；只有改动过 `src/` 里的代码才需要重新 build。

## 从 GitHub 安装（开源后给用户用）

```bash
dsh plugin --profile web add github:用户名/仓库名
```

锁定分支/标签：

```bash
dsh plugin --profile web add github:用户名/仓库名#main
```

> 原理：`dsh plugin add` 把参数转发给 pnpm，pnpm 原生支持 `github:user/repo` 拉包；`lib/` 构建产物已提交，拉下来即成品，无需构建，`dsh.bundle` 声明会让它自动挂载为 profile 层。
> 注意：安装的是**仓库克隆副本**——本地改代码并 `pnpm build` **不会**影响它；要更新需重新执行上面的 add 命令拉取最新。

> 安装后需**重启 dsh web** 使插件层生效（激活层在启动时加载）。

## 安全说明

- 测试插件请使用上述**官方安装/卸载命令**，不要手动修改 dsh 的配置文件（`$DSH_HOME` 下）。
- 仓库不提供 `--patch` 本地加载配置。
